# 2026-07-03

## Compact mode (title-only cards)

- New board-toolbar toggle (`rows-2` icon, next to the Select button): **compact mode**. Off by
  default. When on, board cards show only the title — covers, fields, countdown badges,
  relationship chips, footer all hidden via CSS (`kap-compact` class on `.kap-board-host`,
  `styles.src.css`). Card height equalization re-runs on toggle, so cards shrink to title height.
- Persisted per view as `compactMode` in `this.config` (same flat-key mechanism as
  `calendarMode`/`triageMode` → written into the `.base` file). Reader: `readCompactMode`
  (`view-config.ts`, default-on-missing) + spec.
- Board mode only: the class is dropped in calendar/triage so the scheduling panel and triage
  card keep their full layout.
- Tooltips: "Show titles only" / "Show card details"; active state uses `kap-nav-btn-active`.
- Live-verified in the vault (Actions Base → "Kanban: Tasks"): toggle on → title-only cards +
  `compactMode: true` in the `.base`; detach/reopen → compact restored; toggle off → full cards +
  `compactMode: false`. `dev:errors` clean (only unrelated other-plugin noise). Screenshot taken.
  Fixture note: the view now carries an explicit `compactMode: false` (≡ absent).
- Docs: `docs/usage.md` (new "Compact cards" section + remembered-state list), `README.md` and
  `docs/README.md` feature bullets, Business Rules rule 24 extended.

## Column collapse persistence — verified working, no change needed

- User reported collapsed/expanded columns forgotten across close/reopen. Live-verified (Actions
  Base, "Kanban: Tasks") that issue #19's persistence works in every scenario:
  collapse → `collapsedColumns: [10 - Backlog]` written to the `.base` immediately; restored
  after leaf detach/reopen; restored after a full `app:reload`; per-view state kept (no leak)
  across a view-switch round-trip (Tasks → Projects → Tasks) in the same leaf.
- `BasesViewConfig.get/set` is an immediate in-memory map (per obsidian.d.ts), so the
  `collapseInitialized` first-rebuild latch has no read-before-populate race in practice.
- Conclusion: already implemented + working on current build; no commit. If the user still sees
  it forget, capture the exact repro (plugin version, embedded base vs leaf, sync involved).
